## Cross-cutting findings worth the evaluator's attention

1. **The entity-extraction layer (module 01, Tier 3) is regex/keyword-based, not AI/NLP.** The PS explicitly asks for "AI, NLP... to automatically extract and structure information." The actual extraction technique is deterministic pattern matching — real, working, and honestly labeled in the code's own health-check output, but it should not be presented to a judge as "AI/NLP extraction." The OCR (Docling) and semantic search (sentence-transformers) components genuinely are ML-based and can honestly be called AI.
2. **Two of three module-05 predictive-ML pillars are unfitted in this checkout** (Isolation Forest, XGBoost — both `UNFITTED_FALLBACK`, live-confirmed, zero `.joblib` artifacts exist anywhere under module 05). Only the deterministic rules engine is active. The system degrades gracefully and discloses this honestly via a live status field — it does not silently fake a score.
3. **Real-data-trained hazard models exist but are never served.** `real_data/real_trained_models/{stuck_pipe,wellbore_instability}_model_REAL.joblib` are genuinely trained on real Volve data but are not referenced by any runtime code path — confirmed via hash comparison and exhaustive grep (see `06_ML_AND_MODEL_AUDIT.md` for the full two-part reason why, including a dict-key mismatch that would break loading even if the directory were fixed).
4. **No real eRTMAC feed exists or was obtainable** — the physics digital twin is an honest, clearly-labeled substitute, not a fabrication.
5. **"Fishing operations" has no data-model representation** — a genuine, specific MISSING gap directly traceable to explicit PS wording.
6. **The well catalog is a visible hybrid**: 12 procedurally-generated Assam-region wells (27°N) plus 2 real North Sea Volve wells (58°N) — any map view showing all 14 together shows an obviously discontinuous, non-contiguous geography. This is not a bug, but worth being prepared to explain in a demo.
